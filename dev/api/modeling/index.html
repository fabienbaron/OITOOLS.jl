Bandwidth smearing

A model with the global key "smear" => n (2 or more) is averaged over each spectral channel wherever it meets data: model_to_chi2, its gradient, residuals_flat, model_to_obs, every fitter built on them, and simulate_from_oifits. Each channel, EFF_WAVE ± EFF_BAND/2, is sampled at n sub-wavelengths, evenly in wavenumber; V² is the channel mean of |V|², a triple product the mean of the products, a visibility the mean visibility. That is what a power-spectrum estimator measures across a channel, and how PMOIRED and CANDID model it. It matters for a companion near or beyond the smearing radius R λ / (2 B_max) and for a visibility null, which it fills in. Absent, 0 or 1, nothing changes. SPARCO's image + model criterion refuses a smeared model.

"smear" => "auto" chooses n per dataset by CANDID's rule — four samples per cycle of the largest phase change across a channel, at least 3 — for a point at the model's extent (each component's offset plus half its size, as the dict holds them when the model is compiled); smear_samples reports the number.

"smear_mode" => "coherent" averages the visibility over the channel instead and forms the observables from that average: what an ABCD / coherent-flux measurement gives (GRAVITY), and how CANDID models smearing. The default, "incoherent", suits power-spectrum estimators (fringe-scanning combiners). Lachaume & Berger (2013, MNRAS 435, 2501) show the smearing of V² and closure phase depends on the fringe encoding and the estimator; each is an approximation to a given instrument. For a binary the two differ by f²(1 − sinc²).

OITOOLS.companion_search — Function
companion_search(model_dict, data; companion = "comp", free = [companion * ",f"],
                 lb = Dict(), ub = Dict(), fmax = 0.5,
                 step = nothing, rmin = nothing, rmax = nothing, mask = 0.01,
                 weights = [1, 1, 1], solver = :bradi, refine = 0, threads = true,
                 on_grid = nothing) -> CompanionSearch

Search for a companion around the model's primary: on a grid of positions, fit the companion at each node with its position held there, map χ², and report the best node and its significance against the model without a companion.

The model is the primary plus a component companion with keys companion,f, companion,x and companion,y (their values are only starting points; x and y are set by the grid). The primary's flux should be written as 1 - $companion,f, so that the total is 1 at every node. A point companion is a component with no shape key; give it ud (and free it) for a resolved one. Bandwidth smearing follows the model's "smear" setting.

Free at each node: free, which must include companion,f, bounded to [0, fmax].

  • Only companion,f free → the fast path, everything else fixed at the dict's values. Fit the primary first (without the companion) and pass its fitted values.
  • Anything else → the general path, VMLMB with lb/ub (defaults from default_bounds).

The grid (defaults from the data):

  • step λ/(2 Bmax) — half of PMOIRED's λ/Bmax, since the position is not refined at a node;
  • rmax R λ/(2 B_max), the bandwidth-smearing radius, when the data have channel widths;
  • rmin the extent of the primary's analytic components (offset plus radius), at least step;
  • mask: nodes where the primary's image components, convolved with a beam of FWHM λ/B_max, exceed mask times their peak, are not searched. 0 turns it off.

solver (fast path): :bradi, a global 1-D minimisation on [0, fmax] (OptimPackNextGen's BraDi), or :halley, Halley's method from the best of a coarse sampling, falling back to BraDi at any node where it does not converge in the bounds.

weights are those of model_to_chi2; the fast path takes V², T3amp, T3φ, VISAMP and VISPHI.

path = :general uses VMLMB even when only the flux is free, which is how the two paths are compared.

refine: after the grid, the refine best local minima of the map (nodes no worse than any searched neighbour) are each fitted again with fit_model_lsqfit, the companion's position free as well as free: x and y within [-rmax, rmax], the flux within [0, fmax], the rest within lb/ub or default_bounds. Minima that converge within half a step of a better one are merged. The node values are a grid's, at most half a step from the minimum; refining puts the best position, its flux and its significance at the minimum itself, with LM's σ. The map is unchanged. 0 (the default) skips it.

on_grid, when given, is called once the grid is laid out and before any node is fitted, with (; x, y, chi2r, params, nnodes): the axes, and the arrays the search then fills node by node (NaN until a node is done). It is how a window draws the map while the search runs; the arrays are written by the search's threads while the caller reads them.

OITOOLS.detection_sigma — Function
detection_sigma(chi2r_null, chi2r_best, ndof) -> Float64

How many σ the better model is preferred by, as CANDID (Gallenne et al. 2015) computes it: the best model is taken to describe the data (its χ²ᵣ rescaled to 1), the χ² of the null model is then ndof · χ²ᵣ,null / χ²ᵣ,best, and its probability under a χ² distribution with ndof degrees of freedom is converted to the equivalent number of Gaussian σ. Not exact — it trusts the error bars up to a common factor — which is why it is a convention to state.

Spectral lines

A component's flux can carry spectral lines, with PMOIRED's keys and formulas: c,line_<n>_wl0 (µm), c,line_<n>_f (the peak added to the continuum; < 0 for absorption) and one profile with its width in nm — c,line_<n>_lorentzian (FWHM), c,line_<n>_gaussian (FWHM, with an optional c,line_<n>_power), c,line_<n>_truncexp (with c,line_<n>_pow) or c,line_<n>_trunclor (one-sided: redward for a positive width, blueward for a negative one). The component's flux is then its continuum (c,f, or 1) plus its lines at each wavelength, which weights its visibility, so the lines show in V, the phases, the closure phases and the flux. Each key is a parameter like any other: EX5 writes a centre as a velocity, "A,line_brg_wl0" => "2.16612 * (1 + \$vA / 2.998e5)".

Measurement model

How a fit compares the model with spectrally resolved data, given to fit_model_lsqfit as measurement: the model's differential phases referenced to the continuum of each spectral vector, as the pipeline referenced the data (visphi = :continuum), and PMOIRED's spectral kernel (spectral_kernel). A spectral vector is the points of one table row — a baseline, triangle or telescope at one time — across the wavelengths.

OITOOLS.measurement_model — Function
measurement_model(; visphi = :absolute, order = :auto, continuum = nothing,
                  spectral_kernel = 0, pmoired = false) -> MeasurementModel
  • visphi = :continuum — each spectral vector's phase residuals minus a polynomial in λ of order (:auto: PMOIRED's max(2, ⌊ptp(λ_continuum)/0.2 µm⌋)) fitted over its continuum channels: those outside the model's spectral lines (± 1.5 FWHM for a Gaussian, ± 3 widths for a Lorentzian, PMOIRED's widths), and inside continuum (λ ranges in metres) when given. :absolute (default) compares VISPHI as it is.
  • spectral_kernel = k — PMOIRED's wl kernel: the model smoothed along each spectral vector with a Gaussian of FWHM k channels (2⌊2k⌋ + 3 taps, normalised, edges mirrored) — the complex visibility and the complex triple product as phasors, V² on its own — before the observables are compared (and before visphi = :continuum). A compatibility mode reproducing PMOIRED (its setupFit sets k = 2 for GRAVITY); see PLAN_SpectralResponse.md for what it approximates. Smoothed over the channels present: where the data were filtered to a window the window's edges are mirrored, where PMOIRED smooths across them.
  • pmoired = true — visphi = :continuum as PMOIRED's DPHI computes it (computeDiffPhiOI), to reproduce its numbers: the continuum is every channel (a Gaussian or Lorentzian line is NOT left out; a truncexp one is), and the data's polynomial is fitted weighted by 1/σ² but the model's unweighted (its visibilities carry no errors): (d − Pw d) − (m − Pu m). The default fits one polynomial, weighted, to the residuals over the channels away from the lines.

Many starts

multistart_fit is PMOIRED's gridFit: Levenberg-Marquardt from every node of a grid (grid = ["p" => (min, max, step)]) and/or from uniform or normal draws (rand, randn, nstarts), starts outside constrain dropped, then the fits sorted as PMOIRED's analyseGrid does — set aside when failed, without uncertainties or unmoved, the rest grouped into distinct minima, lowest χ²ᵣ first. An explored parameter that is fixed in the model is held at each start's value (PMOIRED's grid parameter in doNotFit): a grid over held parameters is a χ² profile, every node fitting the rest. The fits run on threads, one compiled model each; start i draws from Xoshiro(seed + i), so the result does not depend on the thread count. For a component on an orbit, minima whose MJD0 differ by whole periods are one.

r = multistart_fit(m, ["B,f", "B,x", "B,y"], data; weights = [0, 0, 1, 1, 0, 0, 0],
                   grid = ["B,x" => (-12, 12, 1.5), "B,y" => (-12, 12, 1.5)],
                   constrain = [("sqrt(\$B,x^2 + \$B,y^2)", "<=", 12)])
r.minima[1].fit          # the global minimum, an LsqFitResult
OITOOLS.multistart_fit — Function
multistart_fit(model_dict, list_free_params, data; grid, rand, randn, nstarts, constrain,
               lb, ub, weights, constraints, rv, deltachi2, seed, threaded, maxIter, verbose)
    -> MultiStartResult

Levenberg-Marquardt fits (fit_model_lsqfit) from many starting points, and the distinct minima they reach: PMOIRED's gridFit.

The parameters explored, each in one of

  • grid — "p" => (min, max, step): every node, PMOIRED's count ⌊(max − min)/step + 1⌋ from min to max; several grids make every combination (the first varying slowest);
  • rand — "p" => (min, max): uniform; randn — "p" => (mean, σ): normal; one draw per start;

as a Dict (taken by name) or a vector of pairs (in order). With a grid the number of starts is its node count (draws added to each node); without one, nstarts. The other free parameters start from model_dict. An explored parameter that is not free (a fixed number in model_dict) is held at the start's value in that fit — a grid over held parameters is a χ² profile, every node's fit of the rest. A start outside lb/ub is moved onto the bound.

constrain drops starts before fitting: conditions in the form of constraints (("sqrt($B,x^2 + $B,y^2)", "<=", 12), ModelConstraint), held when not violated. constraints, lb, ub, weights, rv and maxIter apply to every fit, as in fit_model_lsqfit.

The fits are then sorted as PMOIRED's analyseGrid does: set aside when they failed, have no uncertainties, moved their explored parameters by less than 1σ in all, or end above the best χ²ᵣ + deltachi2 (when given); the rest grouped — two fits are one minimum when the mean over the free parameters of (bᵢ − bⱼ)²/(σᵢσⱼ), divided by their number, is below 1 (a gridded held parameter counts, with σ half its step) — each minimum kept as its lowest χ²ᵣ. For a component on an orbit, MJD0 values whole periods apart count as the same.

Threads (threaded = true): one compiled model per thread; start i draws its values from Xoshiro(seed + i), so the starts and results do not depend on the thread count.

Orbits and radial velocities

A component on an orbit takes PMOIRED's keys and PMOIRED's definition (_orbit): "c,x" = "c,y" = "orbit", with the elements c,orb P (days), MJD0 (periastron, MJD), e, omega, OMEGA, incl (degrees) and a (mas) — or M (M☉) and plx (mas) in place of a. Its position is computed at each data point's own MJD, once per epoch (an expression of $MJD alone is evaluated once per run of equal MJDs), in Float64 whatever the data's precision. ω is the secondary's, relative to the primary (orbitize!'s convention, 180° from Gallenne et al. 2023's). Each element is a parameter like any other: fixed, free, or an expression.

Radial velocities (read_rv, a CSV MJD,RV,sigma,star with star a or b) are fitted with the interferometry by fit_model_lsqfit(…; rv), fit_model(…; rv) and bootstrap_fit(…; rv), against the velocity elements c,orb Ka, Kb, gamma — or M and q (= Mb/Ma) with incl. chi2 and ndof count them; chi2_rv is their part.

m = Dict{String,Any}("1,ud" => 0.2, "2,f" => 0.37, "2,x" => "orbit", "2,y" => "orbit",
                     "2,orb P" => 42.38, "2,orb MJD0" => 59785.45, "2,orb e" => 0.623,
                     "2,orb omega" => 114.1, "2,orb OMEGA" => 77.4, "2,orb incl" => 71.0,
                     "2,orb a" => 3.75, "2,orb Ka" => 50.3, "2,orb Kb" => 58.8, "2,orb gamma" => 14.9)
rv = read_rv("demos/data/HD210763/rv_gallenne2023.csv")
r  = fit_model_lsqfit(m, ["2,orb e", "2,orb a", "2,orb Ka", "2,orb Kb", "2,orb gamma"], data; rv)

Bounds, constraints and model files

lb/ub describe a box, one parameter at a time. A relation between parameters — a ring's outer diameter exceeding its inner one, two flux fractions summing to one — is not a box, and needs ModelConstraint.

fit_model hands constraints to NLopt as real nonlinear constraints, so they hold at the optimum rather than being encouraged there; an algorithm that cannot take them (including the default :LD_LBFGS) is wrapped in :AUGLAG rather than replaced. fit_model_lsqfit and fit_model_nested have no such machinery and use a one-sided quadratic penalty on the normalised violation, matching PMOIRED's prior list — soft, and so able to lose to a steep χ². The distinction is worth knowing before choosing a fitter for a constrained model.

A model dict alone does not describe a fit: the free list, the bounds, the constraints and the priors all change the answer and none of them lived in a file before. A TOML model file carries all five.

free = ["star,ud", "disk,pa"]

[model]
"star,ud"   = 6.5

OITOOLS.fit_model_pigeons — Function
fit_model_pigeons(model_dict, list_free_params, data; lb, ub, weights, constraints,
                  n_chains = 10, n_rounds = 10, explorer = :slice, variational = false,
                  n_chains_variational = 0, reference_sigma = 3.0, seed,
                  multithreaded = Threads.nthreads() > 1, verb = true) -> SamplerResult

Sample the posterior with non-reversible parallel tempering (Syed et al. 2021) through Pigeons.jl — the sampler for a MULTIMODAL posterior: the chains move between the basins along an annealed ladder from a reference to the posterior. Needs using Pigeons.

The free parameters are mapped to ℝ (a logistic for two finite bounds, lo + exp(z) for one, the identity for none) and the ladder anneals from N(0, reference_sigma²) on those coordinates. The log-likelihood is −(χ² + constraint penalty)/2; the bounds are the prior.

  • n_rounds is a power: the run makes 2^n_rounds scans, each round tuning the ladder for the next. n_chains ≈ 2Λ (the global communication barrier) is the sizing rule.
  • explorer: :slice (no gradient) or :mala (AutoMALA, on the closed-form χ² gradient).
  • variational = true fits a Gaussian reference during the run; n_chains_variational > 0 keeps a fixed leg beside it (the stabilised variant, Surjanovic et al. 2022), which guards against the variational fit collapsing onto one mode. An interferometric posterior is usually far narrower than its bounds, and the fixed reference's ladder then never communicates: on AX Cir's binary (4 parameters, bounds ±60 mas), 0–1 round trips at 8–10 rounds with the fixed reference, 76–352 with the variational or stabilised one, the evidence settled to 0.03.

logz is the stepping-stone evidence on fit_model_nested's scale (the log volume of the bounds subtracted), NaN when a bound is infinite; logzerr is 1/√(round trips), which does not include the estimator's bias in a short run: on α Cen A's power-law fit, against Nautilus's −712.528, it gives −711.71 at 8 rounds (1 round trip), −712.29 at 10 (18) and −712.536 at 12 (103). Read an evidence from enough rounds for tens of round trips. diagnostics carries the round trips — fewer than 3 and the ladder was barely traversed, so the other modes may not have been visited.

OITOOLS.eval_model_sub — Function
eval_model_sub(model, x, uv; wl, dlam, mjd = nothing, nsub = model.smear, n = 0)
    -> Matrix{Complex{T}}

The model's visibilities across each spectral channel: an N × nsub matrix whose column k holds every uv point at its channel's k-th sub-wavelength.

A channel is wl ± dlam/2 (metres, per point or one value for all), sampled at the midpoints of nsub equal steps in WAVENUMBER, a flat spectrum across the channel. A point's uv, which is its baseline over the channel's central wavelength, is rescaled to each sub-wavelength, and $WL takes the sub-wavelength. An image component keeps the channel's own plane at every sub-wavelength. A point with no width (dlam 0 or not finite) repeats its central value.

The observables are averaged over the columns — V² as the mean of |V|², a triple product as the mean of the products — which is what a power-spectrum estimator measures across a channel and how PMOIRED and CANDID model bandwidth smearing. The χ² functions, residuals_flat and model_to_obs do that for a model with "smear" => nsub (2 or more) when the data carry channel widths.

OITOOLS.default_bounds — Function
default_bounds(model_dict, list_free_params; data = nothing, max_size = nothing) -> (lb, ub)

Suggest lower and upper bounds for each free parameter, as two Dict{String,Float64} ready to pass to any fitter's lb/ub keyword.

Bounds are chosen from the parameter's suffix — the part after the first comma, so "star,ud" is looked up as "ud". Azimuthal-mode keys ("c,az amp1", "c,az projang1") are recognised by prefix. Anything unrecognised, including bare global names, gets (-Inf, Inf); callers that need finite bounds (nested sampling) should check for that.

Angular sizes and offsets are the only bounds worth tuning, and they are the ones the data can tune. Pass data and the ceiling becomes 2 λ/B_min from the actual uv coverage — the array cannot constrain a source larger than the scale its shortest baseline senses. Without data the ceiling is DEFAULT_MAX_SIZE_MAS; max_size overrides both.

lb, ub = default_bounds(model_dict, free)              # 100 mas ceiling
lb, ub = default_bounds(model_dict, free; data = data) # sized to this uv coverage

Everything else is physical rather than instrumental — fluxes in [0,Inf), since a flux is a weight relative to the others, thick in [0,1], inclination in [0,90], position angles in [-180,180], an azimuthal amplitude az ampN in [0,1] — and does not depend on the data. The amplitude multiplies the brightness by 1 + amp·cos(…), so 1 is the largest single amplitude that keeps it non-negative; several modes need Σ amp ≤ 1, which a box cannot say. PMOIRED leaves the amplitude unbounded, so a PMOIRED fit can report one above 1.

A nested sampler needs a finite upper bound on every free flux, since the bounds are its prior.

See also display_model, which validates values against whatever bounds you end up with, and max_angular_scale.

OITOOLS.ModelConstraint — Type
ModelConstraint(lhs, op, rhs; tol = DEFAULT_CONSTRAINT_TOL)

A relation between model parameters, enforced during fitting.

lhs and rhs are parameter names ("disk,diamout"), expressions over parameter names ("2 * star,ud"), or — for rhs — a plain number. op is one of "<", "<=", ">", ">=", "=", given as a string or a symbol. tol is how much violation counts as none; see DEFAULT_CONSTRAINT_TOL.

fit_model hands these to NLopt as real nonlinear constraints, so they hold at the optimum. fit_model_lsqfit and fit_model_ultranest have no such machinery and apply a one-sided quadratic penalty instead, which is soft: a steep enough χ² can overrule it, and tol then sets the stiffness rather than a feasibility tolerance.

ModelConstraint("disk,diamout", ">", "disk,diamin")   # a ring must have an outside
ModelConstraint("star,f", "+", 0.0)                   # ── invalid: `+` is not a relation
ModelConstraint("star,f + disk,f", "=", 1.0)          # fluxes sum to one
ModelConstraint("star,ud", "<", 4.0; tol = 0.01)      # deliberately loose

Globals — model keys with no comma — must be written with a \$, as "\$PA", exactly as in a model expression. A bare name with no comma and no arithmetic is taken to be one and gets its \$ added.

See also fit_model and read_model_file.

Fit a parametric model by Bayesian nested sampling, returning the posterior and the evidence as well as a best-fit point.

Unlike the gradient fitters this needs no starting guess — it samples the whole prior volume — but it does need finite bounds on every free parameter, since those bounds are the prior.

using OITOOLS, Nautilus
r = fit_model_nested(model_dict, ["star,ud"], data;
                     lb = Dict("star,ud" => 0.5), ub = Dict("star,ud" => 10.0))
r.logz, r.logzerr        # the evidence, for comparing models
r.posterior              # equally weighted samples, (n_samples, n_params)

backend selects the sampler and defaults to nested_backend(); see set_nested_backend! to change it for a session.

Evidence from two different samplers is worth more than evidence from one: logz should agree within logzerr, and NestedResult.backend records which produced any given number.

Nautilus is importance nested sampling

:nautilus draws from neural-network-boosted importance shells rather than by rejection inside a bounding ellipsoid, which buys it far more effective samples per likelihood call. Measured on the α Cen A and α Cen B power-law fits, its logzerr is 0.019 against UltraNest's 0.18–0.31 on the same data, while x_opt agrees to four decimals — so the two can be cross-checked against each other and the Julia one gives the tighter evidence.

threaded defaults to Threads.nthreads() > 1; seed makes a run reproducible.

OITOOLS.model_warnings — Function
model_warnings(model_dict, list_free_params; lb, ub) -> Vector{String}

Everything wrong with a model that can be seen without fitting it, one sentence each.

Four of the first five describe a setup that runs happily and answers the wrong question: a starting value outside its own bounds, bounds that exclude everything, and fluxes that cannot make a visibility. The visibilities are divided by the total flux, so the fluxes' scale is free: when every flux is free the fit has one direction that changes nothing (fix one, or write one as 1 − the others), and numeric fluxes summing to zero or less make V undefined.

The fifth, an expression referring to a parameter that is not in the model or to an implicit variable its kind of expression cannot see ($WL inside a profile), does not run at all: the resolver raises UndefVarError:fsnot defined inOITOOLS.RGF`` at EVALUATION time, naming its own internal module rather than the key or the expression at fault. Removing a component or a global leaves exactly that behind in anything that referred to it, so the model panel reports it here instead.

The sixth is a key the parser ignores. A key that is not a shape key and that no expression refers to does nothing, whether it was added with "+ parameter" and is not used yet or is a misspelling (star,diamm); the warning says it is not used. A shape key of another kind beside the one that decided the component does nothing either: ud and diamin make a ring, whose ud is not read. Neither raises; in the second case the warning says what the component was read as and which key decided it.

The seventh is a wavelength written in metres: $WL is in microns, so $WL/1.6e-6 is off by 10⁶; a constant below 1e-3 set against $WL is reported.

display_model reports the first five. It calls this function for the reference check alone and keeps the bound warnings in its own per-parameter table, where each one reads beside the bounds it is about.

Flux fractions given as expressions are not checked: their values depend on the resolver, so summing the literals would be summing the wrong things.

OITOOLS.bootstrap_fit — Function
bootstrap_fit(model_dict, list_free_params, data; kwargs...) -> BootstrapResult

Estimate parameter uncertainties by nonparametric block bootstrap: refit the model to nboot replicates in which the blocks of data (by default one per MJD and telescope configuration) are resampled, and summarise the scatter of the best-fit parameters.

Unlike the analytic covariance of fit_model_lsqfit, this does not assume the quoted error bars are correct or uncorrelated: correlated calibration errors and mis-stated error bars show up as extra scatter between replicates. It does assume the blocks are numerous and exchangeable — with a single snapshot (a handful of blocks) the estimate is unreliable, and perturb_data based Monte Carlo or the analytic errors are the better tool.

Arguments

  • model_dict::Dict{String} — flat parameter dictionary
  • list_free_params::Vector{String} — names of the free parameters
  • data::OIdata — interferometric data

Keywords

  • nboot — number of replicates (default 200; use ≥1000 for stable percentiles)
  • mode — :replacement (default), :halfsample or :weights; see block_counts and block_weights. :pmoired reproduces PMOIRED's scheme and is biased low by about √2 — comparison only
  • granularity — :config (default), :epoch or :point; see data_blocks
  • fitter — :lsqfit (default, Levenberg-Marquardt with analytic Jacobian) or :nlopt
  • rv — radial velocities (read_rv) fitted with the interferometry (:lsqfit); each replicate resamples them with replacement, as it resamples the blocks
  • lb, ub, weights, nB_workspace — passed through to the fitter
  • method, maxeval — NLopt settings (fitter=:nlopt)
  • maxIter — LsqFit iterations (fitter=:lsqfit)
  • start_scatter — perturb each replicate's starting point by this many σ of the full-data fit (default 0; PMOIRED uses the equivalent of 1). Non-zero values mix optimiser scatter into the uncertainty and are meant for comparison studies only.
  • sigma_clipping — reject replicates beyond this many σ from the median (default nothing; PMOIRED's plots default to 4.5)
  • chi2r_max — reject replicates whose reduced χ² exceeds this value
  • seed — RNG seed; replicate i uses Xoshiro(seed + i) so results are reproducible regardless of thread scheduling
  • threaded — run replicates on all available Julia threads (default true)
  • verb — progress reporting (default true)

Example

data  = readoifits("data/AlphaCenA.oifits")[1,1]
model = Dict{String,Any}("star,ldlin" => 8.0, "star,u" => 0.3, "star,f" => 1.0)
boot  = bootstrap_fit(model, ["star,ldlin", "star,u"], data;
                      lb=Dict("star,ldlin"=>5.0, "star,u"=>0.0),
                      ub=Dict("star,ldlin"=>12.0, "star,u"=>1.0),
                      weights=[1.0, 0.0, 0.0], nboot=500)

OITOOLS.bootstrap_driver — Function
bootstrap_driver(fitfun, x_opt, list_free_params; kwargs...) -> BootstrapResult

Run nboot bootstrap replicates of an arbitrary fit and summarise the scatter of the resulting parameters.

This is the model-agnostic half of bootstrap_fit: it owns the replicate loop, the seeding, the threading, the failure handling, the clipping and the statistics, and knows nothing about what is being fitted or how the data are resampled. Packages with their own estimators (or their own notion of a resampling unit) can reuse the statistics by calling this directly.

Arguments

  • fitfun(state, rng) -> (x, chi2r) — performs one replicate: it resamples the data and fits them, returning the best-fit parameters and the reduced χ². The driver never resamples; that is deliberate, so that callers are free to resample structures OITOOLS knows nothing about. A third element may be returned, (x, chi2r, extra), which is stored in info (see below).
  • x_opt — best fit to the unresampled data, recorded in the result.
  • list_free_params — parameter names; length sets the expected width of x.

Keywords

  • nboot — number of replicates (default 200)
  • worker_init(w::Int) -> state — build per-worker state, called once per worker and serially, before any task is spawned (compiling or allocating concurrently is exactly what this exists to avoid). state is nothing when worker_init is not given.
  • nworkers — number of replicate-level workers; 0 (default) means min(nthreads(), nboot). Set it to 1 when fitfun threads internally, so the two levels do not oversubscribe.
  • info — optional AbstractVector of length nboot; when given and fitfun returns a third element, info[i] receives it. Written at the replicate's own index, never in completion order.
  • sigma_clipping, chi2r_max — reject replicates beyond this many σ from the median, or above this reduced χ²
  • seed — replicate i uses Xoshiro(seed + i), so results do not depend on thread scheduling
  • threaded — use several workers (default true; ignored if nworkers is set)
  • verb — progress reporting
  • mode, granularity, nblocks — metadata only, copied into the result

Example

# a fit with no data at all: recover the scatter of a known Gaussian
x_true = [1.0, 2.0]
r = bootstrap_driver((state, rng) -> (x_true .+ 0.1 .* randn(rng, 2), 1.0),
                     x_true, ["a", "b"]; nboot = 500, seed = 1, verb = false)
r.sigma   # ≈ [0.1, 0.1]

OITOOLS.data_blocks — Function
data_blocks(data::OIdata; granularity=:config, mjd_digits=5) -> DataBlocks

Partition data into resampling blocks.

Granularity

  • :config (default) — one block per (MJD, telescope configuration), where the configuration is the baseline for V²/VIS, the triangle for T3 and the telescope for FLUX. All wavelength channels of a block stay together, and observables sharing a configuration at the same MJD (e.g. |V| and V² on the same baseline) stay together too. This is PMOIRED's "spectral vector".
  • :epoch — one block per MJD: an entire observation, all baselines and all observables, is kept or dropped as a unit. Coarser, more conservative; needs many epochs to be usable.
  • :point — one block per data point. The classical i.i.d. bootstrap; it destroys the spectral and per-configuration correlation structure and will therefore underestimate uncertainties on real data. Provided for comparison studies.

mjd_digits sets the rounding used to group MJDs into a common epoch (default 5 decimals ≈ 0.86 s, matching PMOIRED).

MJD precision

Blocking needs the MJDs at full precision: near MJD 55000 the representable Float32 values are 3.9e-3 d = 5.6 minutes apart, so exposures closer than that would collapse onto one value and their blocks would merge. readoifits therefore stores v2_mjd, t3_mjd, vis_mjd and flux_mjd as Float64 whatever T is — the block structure is identical at T=Float32 and T=Float64. (uv_mjd, the model's time, is Float64 too.)

OITOOLS.block_counts — Function
block_counts(nblocks, mode; rng) -> Vector{Int}

Multiplicity drawn for each block under the given resampling mode. Exposed mainly for testing and for the calibration study of the different schemes.

Modes

  • :replacement (default) — draw nblocks blocks with replacement. This is the textbook nonparametric bootstrap; multiplicities are ≈ Poisson(1), i.e. mean 1 and variance 1.
  • :halfsample — keep a random half of the blocks, each once. Balanced repeated replication: correctly calibrated (the finite-population correction cancels the factor 2 from halving the data), and cheaper since each replicate fit uses half the data. In the validation study under demos/bootstrap_validation this was the best-calibrated scheme whenever blocks were numerous (ratio 0.94-1.06); with very few blocks it turns conservative (1.24-1.56), since each replicate then fits very little data.
  • :pmoired — PMOIRED's scheme: build two independent copies of the dataset, drop a random half of the blocks in each, and fit the union. Multiplicities are 0/1/2 with probabilities 1/4, 1/2, 1/4, so their variance is 1/2 rather than 1.
`:pmoired` is biased low by √2 — for comparison only

Because its block multiplicities have variance 1/2 instead of 1, this scheme returns uncertainties that are too small by roughly a factor √2. Measured against simulated truth (demos/bootstrap_validation) it gives 0.62–0.79 of the true parameter scatter in every regime tested, with a 1σ coverage of ~0.50 instead of 0.683. Use it to reproduce or cross-check a PMOIRED result, never to quote an error bar: use :replacement (default) or :halfsample for that.

resample_blocks additionally accepts mode=:weights, the multiplier (Bayesian) bootstrap, which draws continuous weights rather than integer multiplicities — see block_weights.

OITOOLS.block_weights — Function
block_weights(nblocks; rng) -> Vector{Float64}

Random weights for the multiplier ("Bayesian") bootstrap: nblocks draws from Dirichlet(1, …, 1) rescaled to mean 1, i.e. mean 1 and variance 1 − 1/nblocks, the same first two moments as the multiplicity of a draw with replacement.

Unlike block_counts, these are continuous: no block is ever dropped entirely and none is duplicated, so a replicate costs exactly one dataset instead of one-and-a-bit. See apply_block_weights.

OITOOLS.apply_block_weights — Function
apply_block_weights(data, blocks, w) -> OIdata

Multiplier bootstrap replicate: instead of duplicating and dropping blocks, give block i the weight w[i] in the χ² by dividing its error bars by sqrt(w[i]).

For a weighted least-squares fit this is the standard multiplier (or Bayesian) bootstrap: with mean(w) = 1 and var(w) = 1 it has the same asymptotic behaviour as resampling blocks with replacement, at the cost of one dataset per replicate and with no discrete jumps as blocks enter and leave.

The reduced χ² of such a replicate is not meaningful; the parameter scatter is.

OITOOLS.perturb_data — Function
perturb_data(data::OIdata; rng=Random.default_rng()) -> OIdata

Return a copy of data with independent Gaussian noise added to every observable, each draw scaled by that point's error bar. uv coordinates, flags and the number of data points are unchanged.

Useful for building noisy realisations of a dataset — simulation, end-to-end tests, sensitivity checks.

Not an uncertainty estimator

Refitting perturb_data replicates is a parametric Monte Carlo, not a bootstrap: it assumes the quoted error bars are correct and uncorrelated, so it can only ever reproduce the analytic covariance of the fit. In the validation study under demos/bootstrap_validation it was never better than fit_model_lsqfit's covariance and, when calibration systematics were present, it understated the true scatter by a factor 11 to 25. Use bootstrap_fit for uncertainties.

Visibility functions

Evaluate a model's visibilities through the model dictionary:

model = dict_to_model(Dict{String,Any}("star,ud" => 6.5, "star,f" => 1.0), String[])
V     = eval_model(model, Float64[], data.uv)

The geometry kind names are listed with their parameters under Parametric models above.

eval_model returns ComplexF64, with the imaginary part exactly zero for a component at the centre — a component's phase comes from its offset. Code that only wants the modulus should take real.() or abs.() at the boundary rather than carrying complex arithmetic downstream.

Build the model once, outside the loop. Naming the parameters free and passing their values to eval_model gives bit-identical results to baking them into the dict, and dict_to_model is ~10 µs against ~3 µs for the evaluation itself — so rebuilding it per call dominates at the few hundred uv points of a single epoch:

model = dict_to_model(Dict{String,Any}("star,ud" => 6.5, "star,f" => 1.0), ["star,ud"])
V     = eval_model(model, [diameter], data.uv)     # vary the value, keep the model

OITOOLS.vis_ud — Function
vis_ud(θ, ρ)

Visibility of a uniform disc of diameter θ, V = 2J₁(t)/t with t = πθρ.

θ is in mas and ρ = √(u²+v²) in cycles/rad, which is the unit OIdata.uv is stored in – so ρ = sqrt.(uv[1,:].^2 .+ uv[2,:].^2) and nothing needs converting. The result is real and normalised to 1 at ρ = 0; a component's phase comes from its offset, which belongs to the model geometry rather than here.

Any parameter may be a vector as well as a scalar, so a diameter that varies with wavelength needs no loop.

Note

The standalone visibility_*(param, uv) functions were removed in 0.13.2 — the defect was the calling convention, a packed parameter vector read by index, not the per-component functions themselves. vis_ud and the rest above are that same physics with named arguments. Porting an old call: visibility_ud([D], uv) → vis_ud(D, ρ), and visibility_Gaussian([FWHM, i, ϕ], uv) → a dictionary with "c,fwhm", "c,incl" and "c,pa" => 90 - ϕ — the old angle was measured from the u axis, pa is a position angle, and mapping it straight across misorients the ellipse without raising anything.
